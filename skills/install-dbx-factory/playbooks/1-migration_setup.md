Playbook: Set up the engagement end to end: ingest target profiles, create durable `.migration/` working memory, pin tolerances, fire access requests, and close one STOP A per `stop_mode`.

## Phase 1: Ingest the target state

Read reference implementations, standards, and skills per surface. Record each field as FACT or PROPOSED, mark out-of-scope surfaces N/A, reconcile shared conventions into CORE, and persist `<Estate>_target_state.md` plus its knowledge note.

| Profile | Applies to | Keep in the profile |
|---|---|---|
| CORE | all workloads | UC layout, Delta, naming, language, repo/bundle, CI, tests, secrets |
| SQL | SQL objects and reports | dialect, equivalence, materialization, performance, output contract |
| PIPELINE | ETL mappings/jobs | runtime, layers, loads, rejects, restart, parameters, logging |
| ORCHESTRATION | schedules/triggers | Jobs or retained scheduler, dependencies, calendars, alerts, backfills |
| CONSUMER | dashboards, extracts, APIs | re-point/rebuild, auth, SLA, format |
| LAKEBASE | OLTP track | Autoscaling project, branch-per-batch, Postgres 17, constraints, identity, app repoint |
| ML-SCORING | training/scoring | framework, seeds, parity tolerance, features, registry |
| DATA / DEPENDENCY | all workloads | federation/Connect, dual-write, targets, masking, samples, decommission |

Every child uses CORE + its workload profile + DATA / DEPENDENCY. No downstream playbook guesses a missing profile.

## Phase 2: Workspace, tolerances, and access

| `.migration/` file | Purpose |
|---|---|
| `00_context.md` | engagement facts, topology, contacts, glossary |
| `01_conventions.md` | branch/PR and working conventions |
| `03_recon_tolerances.md` / `.json` | human and `dbx-recon` parity contracts |
| `04_dependency_register.md` | append-only dependency entries |
| `05_progress.md` | generated by `skills/migration-fanout/progress.py` from `waves/*.result.json` |
| `06_decisions.md` | dated decisions with provenance and blast radius |
| `07_access_checklist.md` | D10 requests and evidence |
| `allowed_targets.json` | write scope read by recon and the guard |
| `09_capabilities.json` | factory-doctor identity, host, harness, hooks, source principal, stop mode |

### Procedure
1. Consume `00_intake_template.md`, probe what it leaves blank, and propose only what neither source nor probe can answer.
2. Write `00_context.md` with `## Glossary`, `01_conventions.md`, and the target-state cites. Read the process contract from `references/contract.md`; do not restate it.
3. Pin exact-match or per-type/per-surface tolerances, row and aggregate thresholds, populations, nondeterminism, ML parity, legacy-query cap, LIVE/DEGRADED mode, amendment procedure, and matching JSON fields; every rate names its population and every amendment preserves the old row and re-verification scope.
4. Initialize `04_dependency_register.md`, `06_decisions.md`, and the generated-ledger workflow; never hand-edit `05_progress.md`.
5. Probe legacy read, Databricks query, and target write; record WORKS/BLOCKED evidence and fire every blocked item as a D10.
6. Record the three principal tiers in `07_access_checklist.md`:

| Tier | Rights |
|---|---|
| Assessment | metadata and legacy read-only |
| Migration | scoped legacy read-only plus migration-catalog writes; no legacy DDL/DML or production grants |
| Cutover | customer-held production repoint rights, used once at STOP E |

7. Commit `.migration/allowed_targets.json` before STOP A:

| Field | Meaning |
|---|---|
| `catalogs`, `legacy_sources` | designated migration catalogs and named legacy sources |
| `guard_mode`, `target_hosts` | block/warn policy and writable fixture/Lakebase hosts |
| `bundle_targets`, `lakebase_projects`, `lakebase_branches` | bundle, project, and branch allowlists |
| `run_mode`, `fixture_endpoints` | `live` or `fixture`, plus required local cloud endpoints |

Example: `{"catalogs":["mig_cat"],"legacy_sources":["LEGACY_DSN"],"guard_mode":"block","target_hosts":["MIG_DSN"],"bundle_targets":["migration"],"lakebase_projects":["project"],"lakebase_branches":["mig-*"]}`. Adding a catalog, host, or target later is a decision, never an edit. Add `.migration/.hook_probe_nonce` and `.migration/live_playbooks.json` to `.gitignore`; bootstrap `.migration/playbooks.lock.json` with `install-dbx-factory` when absent, then run the setup doctor and commit `09_capabilities.json`.
8. Attach target state, tolerances, and access checklist at STOP A; record proposed defaults and every D10 honestly.

## Specifications
- Deliverable: committed `.migration/` workspace, target-state artifact, knowledge note, and every access gap registered as D10.
- Validation: a fresh session can state scope, tolerances, coexistence mode, and access posture from the committed artifacts.

## Forbidden Actions
Do not invent profiles or tolerances, skip probes, store credentials, or proceed past STOP A with unresolved PROPOSED fields. Always-on rules are in `AGENTS.md`; process rules are in `references/contract.md`.
