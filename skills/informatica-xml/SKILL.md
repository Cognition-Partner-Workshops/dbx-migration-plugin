# Informatica PowerCenter / IICS Dialect

Source-side half of the factory for Informatica PowerCenter 9.x/10.x repository XML exports (IICS exports share the object model and most of the expression language; IICS-only constructs are flagged where they differ). Everything Databricks-side is routed through `skills/target-routing/SKILL.md` to the official `databricks-*` skills; this file cites the section it relies on and never restates product syntax. Read this skill from the four playbooks that call it (`2-estate_inventory`, `3-pipeline_analysis`, `5-unit_migration`, `6-data_reconciliation`); the harness reads `canonicalization.json` next to it.

For an ETL platform the template's vocabulary maps as follows: "system-catalog queries" are read-only repository queries (`REP_*` MX views, `pmrep` listing) plus XML-export file patterns; "type map" is Informatica port datatypes to Delta and Lakebase types; "function and operator map" is the Informatica expression language plus transformation semantics; "procedural constructs" are workflow/worklet control flow, decision/assignment/event-wait/command tasks, session recovery, commit intervals, pre/post SQL, `$$` parameters and lookup cache modes.

Fixture used to harden this skill: `SachetCognition/albion-insurance-data-estate` (read-only): `informatica/XML/*.xml` (5 workflows), `informatica/mapplets/`, `informatica/parameter_files/`, `informatica/scripts/`, `informatica/legacy_shared_services/` (three full-fidelity PowerCenter exports with sessions, Source Qualifier overrides, Router, Update Strategy, Command tasks), `orchestration/` (Control-M export, cron dump) and `docs/`. Where a row below cites `[fixture: file]` the construct was verified against that file's XML/SQL text, not against a live engine.

## 1. Enumeration

Units are mappings, grouped by workflow. Parse the repository XML export: `FOLDER/MAPPING`, `SESSION` (runtime config), `WORKFLOW` (orchestration). Census key: folder/mapping name (fully qualified `<repository>.<folder>.<mapping>`; sessions are keyed `<repository>.<folder>.<workflow>.<session>`, which is exactly the section header format of a parameter file, e.g. `[ALB_PROD_REPO.FIN_BILLING.wf_BILLING_PREMIUM_RECON.s_m_BILLING_PREMIUM_RECON]` [fixture: parameter_files/wf_BILLING_PREMIUM_RECON.par]). Sessions and workflows attach to their mapping's unit; reusable transformations and mapplets are shared objects (wave 0).

### 1.1 XML export file patterns (no engine access needed)

One `POWERMART` document per export; `pmrep objectexport` with dependencies produces the full tree, a Designer "Export" of a single object produces a partial one (no `SESSION`, no `WORKFLOW`). Element paths and what to census from each:

| Object class | XML path (under `POWERMART/REPOSITORY/FOLDER`) | Census key | Size signals | Complexity signals |
|---|---|---|---|---|
| Folder | `FOLDER@NAME, @OWNER, @SHARED, @PERMISSIONS, @UUID` | `<repo>.<folder>` | object counts per class | `SHARED="SHARED"` folders are wave-0 candidates (shortcuts point into them) [fixture: MDM_PARTY] |
| Source definition | `SOURCE@NAME, @DATABASETYPE, @DBDNAME`; children `FLATFILE`, `SOURCEFIELD` | `<folder>.<source>` | `SOURCEFIELD` count | `DATABASETYPE="Flat File"` + `FLATFILE@DELIMITED="NO"` = fixed width (`OFFSET`/`LENGTH`/`PICTURETEXT`); `OCCURS>0` or `LEVEL>0` = COBOL/Normalizer input; `FLATFILE@CODEPAGE`, `@NULL_CHARACTER`, `@STRIPTRAILINGBLANKS` [fixture: wf_POLICY_MASTER_DAILY.xml `PLCYMSTR_DAILY`] |
| Target definition | `TARGET@NAME, @DATABASETYPE`; `TARGETFIELD@KEYTYPE` | `<folder>.<target>` | `TARGETFIELD` count | `KEYTYPE="PRIMARY KEY"` present = MERGE/CDC candidate; `DATABASETYPE` decides the target dialect skill for pre/post SQL |
| Reusable transformation | `TRANSFORMATION@REUSABLE="YES"` directly under `FOLDER` | `<folder>.<transformation>` | `TRANSFORMFIELD` count | `@TYPE` (see 1.3); referenced by `INSTANCE@TRANSFORMATION_NAME` from many mappings = shared object [fixture: `LKP_XREF_CLIENT_PARTY`, `LKP_SII_LOB`, `LKP_APF_ACCOUNTS`] |
| Mapplet | `MAPPLET@NAME`; children as for mapping | `<folder>.<mapplet>` | transformations, connectors | consumed via `INSTANCE@TRANSFORMATION_TYPE="Mapplet"`; two consumers = shared [fixture: mapplets/mplt_DQ_PARTY_STANDARDISE.xml, consumed by wf_PARTY_MDM_SYNC and wf_POLICY_MASTER_DAILY per its DESCRIPTION] |
| Mapping | `MAPPING@NAME, @ISVALID, @VERSIONNUMBER`; children `TRANSFORMATION`, `INSTANCE`, `CONNECTOR`, `TARGETLOADORDER`, `MAPPINGVARIABLE`, `ERPINFO` | `<folder>.<mapping>` (unit key) | `INSTANCE`, `CONNECTOR`, `TRANSFORMFIELD` counts; XML bytes | transformation-type mix, `Sql Query`/`Lookup Sql Override` non-empty, `MAPPINGVARIABLE` count, `$$` occurrences, `ISVALID="NO"` (dead unit) |
| Session | `SESSION@NAME, @MAPPINGNAME, @REUSABLE`; children `SESSTRANSFORMATIONINST`, `SESSIONEXTENSION` (`READER`/`WRITER`, `CONNECTIONREFERENCE`), `SESSIONCOMPONENT` (pre/post-session commands and variable assignments), `ATTRIBUTE`, `CONFIGREFERENCE` | `<folder>.<workflow>.<session>` | `SESSIONEXTENSION` count (one per source/target instance), `PARTITION` count | `Commit Interval`, `Commit Type`, `Recovery Strategy`, `Treat source rows as`, `Target load type`, `Enable high precision`, `Pushdown Optimization`, `Truncate target table option`, per-instance `Sql Query`/`Pre SQL`/`Post SQL` overrides [fixture: legacy_shared_services/XML/*.xml] |
| Workflow / worklet | `WORKFLOW@NAME, @ISENABLED, @SCHEDULERNAME, @SUSPEND_ON_ERROR`; children `SCHEDULER/SCHEDULEINFO`, `TASK`, `TASKINSTANCE`, `WORKFLOWLINK`, `WORKFLOWVARIABLE`; `WORKLET` nests the same | `<folder>.<workflow>` | task count, link count | `TASK@TYPE` other than `Start`/`Session` (Decision, Assignment, Event Wait, Event Raise, Command, Email, Timer, Control, Worklet), non-empty `WORKFLOWLINK@CONDITION`, `SCHEDULEINFO@SCHEDULETYPE` (`ONDEMAND` = externally scheduled, look in Control-M/cron), `ISENABLED="NO"` [fixture: all 5 workflows] |
| Session config | `CONFIG@NAME` + `ATTRIBUTE` (`Stop on errors`, `Error Log Type`, `DateTime Format String`, `Pre 85 Timestamp Compatibility`) | `<folder>.<config>` | - | shared by every session that `CONFIGREFERENCE`s it |
| Parameter file | `*.par`/`*.prm` outside the export: `[section]` headers per workflow/session, `$$name=value` (mapping parameters/variables), `$name=value` (session parameters: `$DBConnection_*`, `$InputFile_*`, `$OutputFile_*`, `$BadFileName`, `$PMSourceFileDir`) | path from `TASK/ATTRIBUTE[@NAME="Parameter Filename"]` | lines | any `$`-value that is itself a path with `$$` inside (nested substitution) [fixture: `$OutputFile_BAD_APF=/interface/outbound/finance/BAD_APF_MATCH_$$RUNMONTH.csv`] |
| Shell / SQL wrappers | `scripts/*` (ksh/sh with `pmcmd startworkflow`, `sftp`, `mailx`), `*.sql` run by Command tasks | path | lines | cross-pipeline kicks (a script starting another engine's job), credentials in env vars [fixture: scripts/run_wf_policy_master kicks `run_insurance_bteq.sh`] |
| External schedulers | Control-M `DEFTABLE/FOLDER/JOB@CMDLINE` containing `pmcmd startworkflow -f <folder> <workflow>`, `INCOND`/`OUTCOND`, `CYCLIC`, `TIMEFROM`, `MONTHDAYS`; crontab lines invoking the wrapper scripts | job name | - | a workflow reachable from two schedulers = duplicate-ownership finding [fixture: orchestration/controlm/ALBION_DWH_DAILY.xml, orchestration/cron/crontab_prod.txt] |

Parse with a namespace-free XML parser and the DTD disabled (`powrmart.dtd` is referenced but never shipped; entity expansion must stay off). Attribute values are XML-escaped SQL: unescape `&apos; &lt; &gt; &#xD;&#xA; &#x9;` before handing overrides to the SQL parser of the connection's dialect skill.

### 1.3 Complexity signals per transformation type

Low: Source Qualifier without override, Expression, Filter, Sorter, Union, Sequence Generator. Medium: Aggregator, Joiner, Router, Lookup (static cache), Update Strategy, Rank, mapplet instance, Source Qualifier with `Sql Query`/`User Defined Join`/`Source Filter`. High (hand conversion, budget accordingly): Normalizer, Java, SQL, Stored Procedure, Custom/External Procedure, Transaction Control, HTTP, XML Source/Parser/Generator, Web Services Consumer, Lookup with dynamic cache, Data Masking, Unstructured Data. Session-level: partitions with per-partition overrides, `Pushdown Optimization` other than `None` (the mapping ran as generated SQL on the source database and the mapping logic is not what executed), `Enable high precision = NO` (section 7).

## 2. Lineage extraction

Reads: `SOURCE` definitions plus Source Qualifier SQL overrides (parse the override SQL, not just the source object). Writes: `TARGET` definitions plus update-strategy semantics. Mark INFERRED: any table name built from parameter files (`$$` variables), mapping parameters resolved at runtime, or dynamic SQL in stored-procedure transformations. Parameter files must be collected with the export; without them, lineage over parameterized objects is INFERRED at best.

### 2.1 Reads (FACT when cited from these elements)

| Read edge | Where it is in the XML | FACT / INFERRED |
|---|---|---|
| Relational or flat-file source | `INSTANCE@TYPE="SOURCE"` -> `SOURCE@NAME` (+ `@DBDNAME` owner) bound to a Source Qualifier by `ASSOCIATED_SOURCE_INSTANCE`; physical database from the session `SESSIONEXTENSION@TYPE="READER"/CONNECTIONREFERENCE@CNXREFNAME` | FACT for the object name; the database/host behind a connection name (`TD_BILLING_PROD`) is FACT only if `pmrep listconnections`/`getconnectiondetails` output or the admin-console connection export is in the evidence bundle, else INFERRED |
| Source Qualifier `Sql Query` override | `TRANSFORMATION[@TYPE="Source Qualifier"]/TABLEATTRIBUTE[@NAME="Sql Query"]`; session-level override in `SESSTRANSFORMATIONINST/ATTRIBUTE[@NAME="Sql Query"]` wins over the mapping | FACT: parse the SQL with the connection's dialect skill (`teradata-bteq` for Teradata connections, `oracle-plsql` for Oracle); every table in `FROM`/`JOIN` is a read; the mapping's `SOURCE` list is then only a port-shape declaration [fixture: wf_GSS_PAY_CALENDAR.xml `SELECT MAX(PAY_PERIOD.PP_NUM) ... FROM PAY_PERIOD`] |

### 2.3 Parameter and dynamic-name resolution order

Resolve `$$name` and `$name` in this order, and cite the source of every resolution: (1) parameter file named by the session's `Parameter Filename` attribute (section header must match the session's full key; a workflow-level `[folder.WF:workflow]` section applies to all its sessions); (2) workflow-level parameter file (`WORKFLOW/ATTRIBUTE[@NAME="Parameter Filename"]`); (3) `pmcmd startworkflow -paramfile` in the wrapper script or Control-M `CMDLINE`; (4) `MAPPINGVARIABLE@DEFAULTVALUE` / `WORKFLOWVARIABLE@DEFAULTVALUE`; (5) repository-persisted variable value (only readable live via `pmrep` or `REP_*`; INFERRED otherwise). Built-in `$PM*` variables (`$PMSourceFileDir`, `$PMTargetFileDir`, `$PMBadFileDir`, `$PMCacheDir`, `$PMRootDir`) resolve from the Integration Service process variables, which are not in any export: INFERRED unless the admin-console export is in the bundle. Nested substitution (`$OutputFile_BAD_APF=.../BAD_APF_MATCH_$$RUNMONTH.csv`) is resolved recursively; a `$$` that is never assigned (fixture: `$$RUNMONTH`) is an UNVERIFIABLE-looking edge that this skill reports as INFERRED with the literal template, which is the acceptable outcome for genuinely dynamic constructs.

### 2.4 Scheduler edges (Informatica owns a scheduler; external schedulers usually own it in practice)

- Intra-workflow: `WORKFLOWLINK@FROMTASK -> @TOTASK` with `@CONDITION` (empty = unconditional; otherwise an expression over `$<task>.Status`, `.PrevTaskStatus`, `.ErrorCode`, `.SrcSuccessRows`, `.TgtSuccessRows`, `.StartTime`, `.EndTime`, or workflow variables) [fixture: `$s_m_POLICY_MASTER_DAILY.Status = FAILED` -> `email_FAIL_POLICY_LOAD`]. Worklets contribute their inner links with the worklet instance as the boundary.
- Event Wait: `TASK[@TYPE="Event Wait"]/ATTRIBUTE[@NAME="File Watch Name"]` is an inbound file edge (pre-defined event) or a user-defined event raised by an Event Raise task elsewhere in the same workflow [fixture: `/interface/inbound/plcymstr/PLCYMSTR_D$$RUNDATE.dat`].
- Workflow schedule: `SCHEDULER/SCHEDULEINFO@SCHEDULETYPE` `ONDEMAND` means someone else starts it: grep Control-M `CMDLINE` and crontabs for `pmcmd startworkflow -f <folder> <workflow>` or for the wrapper script name. `RECURRING` with `SCHEDULEOPTIONS`/`RECURRING` children carries the interval.
- Control-M: `JOB@CMDLINE` is the edge target; `INCOND@NAME` are inbound edges from the named job's `OUTCOND` (`<job>-OK`); `CYCLIC="Y" INTERVAL="30M" TIMEFROM/TIMETO` is a windowed cyclic run; `MONTHDAYS="WD1"` is a business-calendar rule with no cron equivalent (section 6). Missing `INCOND`s that the workflow descriptions say should exist are findings, not edges [fixture: `ALB-DWH-0032` has `INCOND ALB-DWH-0031-OK` but none on `ALB-MDM-0003`].
- cron: a line invoking a wrapper that runs `pmcmd` is a second owner; report every workflow with two owners as a D5 decision input rather than choosing one.
- Wrapper scripts: read them for pre-conditions (`if [ ! -e $FNAME ]`), for what they start after the workflow (`run_insurance_bteq.sh`), and for `-paramfile`; each is an edge with the script path as citation.

## 3. Unit definition

One migration unit is a **mapping plus every session that runs it plus the workflow task instances that wire those sessions in**, keyed by `<folder>.<mapping>`. The unit's brief includes: the mapping XML, its session(s) with resolved parameter files, the Source Qualifier/Lookup overrides as extracted SQL files, the pre/post SQL and pre/post-session scripts as files, the workflow fragment (its task, inbound and outbound links) and the external scheduler entries that start the workflow. A workflow with N sessions therefore yields N units plus one orchestration unit (the Lakeflow Job that reproduces the workflow DAG), converted last.

A unit is `shared` (wave 0, converted first, owned by one child) when any of these hold: a reusable transformation (`REUSABLE="YES"`) or mapplet is instanced by two or more mappings; a folder is `SHARED` and referenced through shortcuts from other folders; a target table is written by two mappings, by a mapping and another engine (fixture: `PLCYMSTR` feed consumed by Informatica and by BTEQ `04_stg_policy_360`), or by a mapping and its own Post SQL; a lookup table is read by two or more mappings (`REF_DB.*` in the fixture); a connection object is referenced by sessions in two folders (governance-shared, section 9); a parameter file section is shared by two sessions; a mapping variable persisted by one session is read by another. Reusable sessions (`SESSION@REUSABLE="YES"`) used in two workflows create one unit with two orchestration parents.

## 4. Type map

Informatica transformation datatypes -> Delta: decimal(p,s) preserved exactly (precision loss is a recon failure), string widths dropped (Delta strings are unbounded; flag consumers relying on truncation), date/time to timestamp with the engagement timezone rule. Loss-prone rows: high-precision decimals, packed/COMP fields from mainframe sources, string trailing-space semantics. Lakebase column comes from `databricks-lakebase` `references/synced-tables.md` "Data Type Mapping" (UC type -> Postgres type) and applies only when the unit feeds the OLTP front door (`14-front_door_oltp`).

| Informatica port type (transformation datatype; common native origins) | Delta (analytical track) | Lakebase Postgres | Loss | Canonicalization / handling |
|---|---|---|---|---|
| `decimal(p,s)`, p <= 28 (Teradata `DECIMAL`, Oracle `NUMBER(p,s)`, DB2 `DECIMAL`) with session `Enable high precision = YES` | `DECIMAL(p,s)` | `NUMERIC` | none | `decimal_round` at the port scale guards only against the target's own rounding mode |

## 5. Function and operator map

Default target form comes from the engagement target state (Lakeflow Spark Declarative Pipelines via `databricks-pipelines`, or PySpark on Lakeflow Jobs); use the modern `pyspark.pipelines` API (`from pyspark import pipelines as dp`, `databricks-pipelines` `references/python-basics.md` "Setup"), never `import dlt`. Expressions below are Databricks SQL and are used verbatim in `@dp.materialized_view` / `@dp.table` bodies via `F.expr(...)` or in DBSQL. Transformation mapping to build out per engagement: Source Qualifier -> read + filter/join pushup; Expression -> withColumn chains; Aggregator -> groupBy (watch sorted-input assumptions); Lookup -> broadcast join (connected) / scalar subquery (unconnected); Update Strategy -> `create_auto_cdc_flow` in a declarative pipeline or MERGE in a job task; Router/Filter -> when/filter; Sequence Generator -> identity column or monotonically_increasing_id with the gap-semantics difference recorded; Normalizer, Java/SQL transformations -> flag as high-risk, hand-convert. ## 7. Known traps with recon signature

Stub traps preserved: session-level SQL overrides silently replace mapping logic (always diff session config against the mapping before converting); Informatica implicit type conversion is looser than Spark (explicit casts at every port boundary); high-precision mode changes decimal arithmetic (check the session property before trusting numeric recon).

|---|---|---|---|---|---|
| 1 | Session-level `Sql Query` / `Lookup Sql Override` / `Source Filter` overrides | `SESSTRANSFORMATIONINST/ATTRIBUTE` overrides replace the mapping-level SQL silently; per-partition overrides differ per partition | converted read implements the mapping's SQL only | Tier 1 row count (filters lost) and Tier 3 missing columns | extract the effective SQL per session **and** partition, `UNION ALL` partition variants; no canon |

| 20 | Persisted mapping variables (watermarks) | repository holds the last committed value | none | Tier 1 count on first run (re-extract or skip) | seed the watermark table from the parameter file or a live `pmrep` read; then compare |
| 21 | Fixed-width flat files | `OFFSET`/`LENGTH`, `PICTURETEXT 9(09)V99` implied decimals, `NULL_CHARACTER`, codepage `MS1252`, `LINESEQUENTIAL` | text read + `substr` | Tier 2 `sum` 100x off (implied scale), null-rate drift (null char), Tier 3 shifted fields (offset) | generate the reader from `SOURCEFIELD` attributes; divide by `10^scale` |

## 8. Canonicalization rules

`canonicalization.json` (list form, loaded by `recon.config.load_canon_rules`; rule names are exactly those in `harness/recon/canon.py`). The harness applies each rule to both sides before comparison and binds rules to fields through the unit's mapping spec; `applies_to` documents the intended field classes.

| Row | Rule | `applies_to` | Params | Why this dialect needs it |
|---|---|---|---|---|
| 1 | `decimal_round` | `decimal(p,s)->DECIMAL(p,s)` | `mode: half_up`, `places: 10` | `Enable high precision = NO` (default; every fixture GSS session) computes in double and Informatica `ROUND` rounds half away from zero, which is Python `ROUND_HALF_UP`; `places: 10` is the same default as the Redshift example so that only sub-1e-10 double noise is neutralized and real last-digit errors at the port scale still fail (trap 3). Tighten `places` per unit only under a recorded decision |
| 2 | `datetime_utc_truncate_ms` | `date/time(29,9),TIMESTAMP(6)->TIMESTAMP_NTZ,TIMESTAMP` | `{}` | ports carry nanoseconds and Teradata/Oracle sources carry microseconds, Delta stores microseconds; `SYSDATE`/`SESSSTARTTIME` audit columns and `Pre 85 Timestamp Compatibility` sessions differ below the millisecond (trap 8). Zoned values are normalized to UTC first, which is the right treatment for `timestamp with time zone` ports |
| 3 | `rstrip_spaces` | `CHAR(n),string(fixed-width)->STRING` | `{}` | Teradata/DB2/mainframe `CHAR` origins and fixed-width flat files with `STRIPTRAILINGBLANKS="NO"` deliver padded strings that the mapping may or may not `RTRIM`; `IS_SPACES` ports become `''`; without this rule every padded code column fails Tier 3 for a non-semantic reason (trap 4) |
| 4 | `empty_string_is_null` | `string,varchar->STRING` | `policy: SET_AT_STOP_A` | flat-file `NULL_CHARACTER`, Oracle targets folding `''` to NULL (fixture `ORA_MDM_HUB_PROD`), `REG_EXTRACT` no-match `''` vs NULL, `IIF(c, 'x')` returning `''`; the STOP A policy decides whether the engagement treats them as equal (trap 5, 16) |
| 5 | `null_missing_equiv` | `*` | `{}` | unconnected output ports and lookup ports with no match produce NULL on the legacy side while the converted table may omit the column in a keyed diff document; treats missing and NULL as equal |
| 6 | `collation_casefold` | `STRING` | `enabled_if: case-insensitive compare flags found in census` | only for columns whose legacy comparison was case-insensitive (`REPLACESTR/REPLACECHR/IN` caseFlag 0, Lookup/Joiner `Case Sensitive String Comparison = NO`, Sorter `Case Sensitive = NO` distinct); never globally, because Informatica string comparison is case-sensitive by default (trap 17) |
| 7 | `identity` | `*` | `{}` | explicit no-op for fields that must compare raw (surrogate keys are excluded from Tier 3 instead, trap 19) |

Harness gaps (needed by this dialect, not implemented in `canon.py`; filed in the PR body, never faked in the mapping): `zero_null_equiv` (Informatica `TO_DECIMAL`/`TO_INTEGER` return 0 for non-numeric input where Spark returns NULL: a per-field rule treating 0 and NULL as equal is needed to reconcile like-for-like conversions that chose NULL); `timestamp_offset_shift` (a constant-offset shift for zone-less legacy timestamps written in server local time, so `TIMESTAMP` targets can be compared without hiding sub-hour errors); `codepage_transcode` (normalize 0x80-0x9F characters between `MS1252`/`Latin1` and UTF-8 before string compare); per-field parameters for the same rule (the loader keys rules by name, so one `decimal_round.places` serves every decimal field of a unit even when port scales range 0-9).

## 9. Governance discovery

Informatica's own repository ACLs (folder/object permissions, from repository metadata or the admin console export) govern who edits mappings, and rarely need UC equivalents; record them as inventory context. The governance surface that must migrate lives in the **connections**: each relational/app connection names a service account whose database-side grants are the real access to inventory via that database's dialect skill. Watch: shared connection objects reused across folders (one over-privileged service account serving many workflows is the common finding), and OS-profile/parameter-file paths that carry credentials outside the secret manager.

## 10. Lakebridge coverage delta

No `--source-dialect` flag applies: Informatica is not a listed transpile source in Lakebridge's dialect matrix (`skills/lakebridge/SKILL.md` "Dialect and transpiler matrix"), so every mapping is hand-converted under sections 5-6 after the analyzer inventory. The analyzer may still profile the XML export (`--source-tech` per the labs CLI's `--help` at first use); use its inventory as a cross-check of section 1.4, never as the census of record. SQL text extracted from Source Qualifier `Sql Query`, `Lookup Sql Override`, `Pre SQL`/`Post SQL` **is** transpilable through the connection's dialect flag (`teradata`, `oracle`) and inherits that dialect's SEEDED rows.

SEEDED row mirrored into `skills/lakebridge/SKILL.md` coverage table:

| Dialect | Converts (SEEDED) | Mangles silently (SEEDED; recon signature) | Rejects / hand-convert (SEEDED) |
|---|---|---|---|
| Informatica (`informatica-xml`; no transpiler flag) | analyzer inventory of the XML export only; embedded SQL overrides transpile under the connection's dialect (`teradata`, `oracle`) | n/a for mappings (nothing is transpiled); for embedded SQL, the connection dialect's mangles apply plus lost per-partition/session-level overrides (Tier 1 count drift) | all transformation logic (Expression, Aggregator, Lookup, Router, Update Strategy, Sequence Generator, Normalizer, Java/SQL/Stored Procedure transformations), workflows/worklets/Command/Event Wait/Decision tasks, parameter files, mapping variables, lookup cache modes |

## 11. Risk heuristics

Inputs the census computes per unit (thresholds are suggestions; the inventory ranks by the weighted sum):

| Signal | Source in the export | Low / Medium / High suggestion |
|---|---|---|
| Size | XML bytes of the mapping + its sessions; `TRANSFORMFIELD` count; `CONNECTOR` count | < 50 KB, < 150 ports / < 300 KB, < 600 ports / above |
| Transformation-type weight | section 1.3 classes: low 1, medium 3, high 10 per instance | sum < 10 / < 30 / above |
| Embedded SQL | non-empty `Sql Query`, `Lookup Sql Override`, `User Defined Join`, `Pre SQL`, `Post SQL`, session-level overrides; lines of SQL; per-partition variants | none / one override, < 40 lines / several or partition-variant overrides |
| Dynamic constructs | Stored Procedure / SQL / Java transformations, `~param~` substitution, `$$` in table names or SQL, unresolved `$PM*` paths | none / `$$` only in filters / any dynamic table name or dynamic SQL |
| Parameter surface | count of `$$`/`$` names per session; `.par` sections missing from the bundle; `SETVARIABLE` usage | < 5 resolved / < 15 or one unresolved / any persisted variable or missing `.par` |
| Vendor-function density | count of rows flagged `edge case`/`no equivalent` in section 5 per 100 ports (`INITCAP`, `\|\|`, `TO_DECIMAL`, `REG_*`, `SOUNDEX`, `MD5`, `IIF` two-arg, `GREATEST/LEAST`) | < 3 / < 10 / above |
| External calls | Command tasks, pre/post-session commands, HTTP/Web Services transformations, `pmcmd` to other workflows, other engines' scripts kicked | none / file moves only / cross-engine kicks or SFTP or web calls |
| Orchestration complexity | tasks other than Start/Session, conditional links, worklets, Event Waits, external schedulers referencing the workflow (Control-M + cron), business-day calendars | linear / one conditional or Event Wait / two schedulers, Decision/Assignment tasks, calendar rules |
| Write complexity | `Data driven` + Update Strategy, dynamic lookup cache, Transaction Control, bulk load type, truncate-load with Post SQL, multiple targets with `TARGETLOADORDER` | append only / MERGE or truncate-load / Transaction Control, dynamic cache, bulk with error tables |
| Shared-object fan-out | consumers of each reusable transformation / mapplet / connection / lookup table (section 3) | 1 / 2-3 / more (wave 0, convert first) |
| Precision risk | `Enable high precision = NO` with decimal arithmetic; double->integer ports; `date/time` scale 9 into `TIMESTAMP(6)` targets | none / one of these / several |
| Estate-level defects surfaced in descriptions | `DESCRIPTION` attributes mentioning "hardcoded", "assumes", "drifted", "manual", incident ids | count as findings for the assessment, not as conversion work (fixture: 4 of the 5 workflow exports carry such statements in `DESCRIPTION` attributes) |
