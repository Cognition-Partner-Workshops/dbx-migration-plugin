# Oracle SQL / PL-SQL Dialect (v0)

Source-side half only. Everything Databricks lives in the official plugin skills reached through
`skills/target-routing/SKILL.md`; this file says what Oracle does, where each construct lands, and which
recon tier catches a wrong conversion. Citations use these shorthands:

- `[dbsql:<file>#<section>]` = `databricks-dbsql/references/<file>` section; `[jobs:...]`, `[pipelines:...]`,
  `[lakebase:...]`, `[uc:...]` likewise for `databricks-jobs`, `databricks-pipelines`, `databricks-lakebase`,
  `databricks-unity-catalog`; `[core]` = `databricks-core/SKILL.md`.
- `[docs:<path>]` = `https://docs.databricks.com/aws/en/sql/language-manual/<path>` (opened while writing this skill).
- `[pg17:<page>]` = `https://www.postgresql.org/docs/17/<page>` for the Lakebase (Postgres-compatible, `[lakebase:SKILL.md]`
  "serverless Postgres-compatible database") column. Lakebase-specific product facts come only from `[lakebase:...]`.

Two sub-profiles run through the same sections. **OLTP profile** (`!dbx_migrate_oltp`, playbook 14): the
`POLADM`-style schema an application writes to; target is Lakebase Postgres and the unit must keep tables,
constraints, sequences, triggers and the packages that write them behaving identically. **Analytical profile**:
the `ODS`-style schema fed by GoldenGate/batch (the Albion `GoldenGate -> Oracle ODS -> PL/SQL -> SOAP` chain
in `docs/architecture_overview.md`); target is Delta/DBSQL, MVs go to Lakeflow, jobs go to Lakeflow Jobs.
Section 4 carries both target columns; section 6 says per construct which track it lands on.

## 1. Enumeration

All queries are `SELECT`s against the data dictionary; none writes, locks, or changes a session setting on the
source. Use `ALL_*` when the census identity owns nothing and has been granted `SELECT ANY DICTIONARY` or
`SELECT_CATALOG_ROLE`; `DBA_*` needs that same privilege and sees every schema. Paginate with
`OFFSET :off ROWS FETCH NEXT :n ROWS ONLY` on the `ORDER BY` shown (12c+), or the `ROWNUM` sandwich in §5 on 11g.
Scope every query with `owner IN (:schemas)` from `.migration/00_context.md`; never `owner NOT IN ('SYS',...)`
alone, it pulls in Oracle-supplied schemas.

| Object class | Census key | Read-only query (one statement) | Size / complexity signal | Minimum privilege |
|---|---|---|---|---|
| Table | `OWNER.TABLE_NAME` | `SELECT owner, table_name, num_rows, blocks, last_analyzed, partitioned, temporary, iot_type FROM dba_tables WHERE owner IN (:schemas) ORDER BY owner, table_name` | `num_rows`/`blocks` (stale if `last_analyzed` old), `partitioned='YES'`, `temporary='Y'` (GTT) | `SELECT_CATALOG_ROLE` |
| Column / type | `OWNER.TABLE_NAME.COLUMN_NAME` | `SELECT owner, table_name, column_name, data_type, data_length, char_length, data_precision, data_scale, nullable, data_default, virtual_column FROM dba_tab_cols WHERE owner IN (:schemas) AND hidden_column='NO' ORDER BY owner, table_name, column_id` | `data_type='NUMBER' AND data_scale IS NULL` (§7 trap), `data_type='DATE'`, `CHAR`, `TIMESTAMP(6) WITH [LOCAL] TIME ZONE` | same |
| Constraint | `OWNER.CONSTRAINT_NAME` | `SELECT owner, constraint_name, table_name, constraint_type, r_owner, r_constraint_name, search_condition_vc, status, deferrable, validated FROM dba_constraints WHERE owner IN (:schemas) ORDER BY owner, table_name, constraint_name` (+ `dba_cons_columns` for columns) | FK fan-in, `status='DISABLED'`, `validated='NOT VALIDATED'`, `deferrable` | same |
| Index | `OWNER.INDEX_NAME` | `SELECT owner, index_name, table_owner, table_name, index_type, uniqueness, status FROM dba_indexes WHERE owner IN (:schemas) ORDER BY owner, table_name, index_name` | `index_type` (FUNCTION-BASED, BITMAP, DOMAIN), `status='UNUSABLE'` | same |
| View | `OWNER.VIEW_NAME` | `SELECT owner, view_name, text_length, text_vc, read_only FROM dba_views WHERE owner IN (:schemas) ORDER BY owner, view_name` (`text_vc` truncates at 4000; use `text` LONG via `DBMS_METADATA.GET_DDL` when `text_length > 4000`) | `text_length`, `CONNECT BY`/`PIVOT`/`@dblink` present in text | same (+`EXECUTE` on `DBMS_METADATA` for long text) |
| Materialized view | `OWNER.MVIEW_NAME` | `SELECT owner, mview_name, container_name, refresh_mode, refresh_method, build_mode, fast_refreshable, last_refresh_type, last_refresh_date, staleness, rewrite_enabled, query_len, query FROM dba_mviews WHERE owner IN (:schemas) ORDER BY owner, mview_name` | `refresh_method`, `fast_refreshable`, `staleness`, `query_len` | same |
| MV log | `OWNER.MASTER` | `SELECT log_owner, master, log_table, rowids, primary_key, sequence, include_new_values FROM dba_mview_logs WHERE log_owner IN (:schemas) ORDER BY log_owner, master` | presence = fast-refresh dependency of §7 | same |
| Package spec / body | `OWNER.OBJECT_NAME` (`PACKAGE`, `PACKAGE BODY` as two rows) | `SELECT owner, object_name, object_type, status, created, last_ddl_time FROM dba_objects WHERE owner IN (:schemas) AND object_type IN ('PACKAGE','PACKAGE BODY') ORDER BY owner, object_name, object_type` | `status='INVALID'`; source lines via `SELECT COUNT(*) FROM dba_source WHERE owner=:o AND name=:n AND type=:t` | same |
| Procedure / function (standalone) | `OWNER.OBJECT_NAME` | `SELECT owner, object_name, object_type, status, last_ddl_time FROM dba_objects WHERE owner IN (:schemas) AND object_type IN ('PROCEDURE','FUNCTION') ORDER BY owner, object_name` | line count from `dba_source`; `dba_arguments` for `OUT`/`SYS_REFCURSOR` params | same |
| Package member | `OWNER.PACKAGE.SUBPROGRAM` | `SELECT owner, object_name, procedure_name, subprogram_id, overload FROM dba_procedures WHERE owner IN (:schemas) AND object_type='PACKAGE' AND procedure_name IS NOT NULL ORDER BY owner, object_name, subprogram_id` | `overload IS NOT NULL` (no DBSQL overloads), `dba_arguments.data_type='REF CURSOR'` | same |
| Source text | (feeds all procedural rows) | `SELECT owner, name, type, line, text FROM dba_source WHERE owner IN (:schemas) AND type IN ('PACKAGE','PACKAGE BODY','PROCEDURE','FUNCTION','TRIGGER','TYPE BODY') ORDER BY owner, name, type, line` | lines; density of `EXECUTE IMMEDIATE`, `DBMS_`, `BULK COLLECT`, `PRAGMA AUTONOMOUS_TRANSACTION`, `WHEN OTHERS` | same. Wrapped source (`dba_source.text LIKE '%wrapped%'` first line) is `UNVERIFIABLE`: list it, never unwrap |
| Trigger | `OWNER.TRIGGER_NAME` | `SELECT owner, trigger_name, trigger_type, triggering_event, table_owner, table_name, referencing_names, when_clause, status, description FROM dba_triggers WHERE owner IN (:schemas) ORDER BY owner, table_name, trigger_name` (body from `dba_source type='TRIGGER'`) | `trigger_type` (`BEFORE EACH ROW`, `COMPOUND`), `status='DISABLED'`, body lines | same |
| Sequence | `OWNER.SEQUENCE_NAME` | `SELECT sequence_owner, sequence_name, min_value, max_value, increment_by, cycle_flag, order_flag, cache_size, last_number FROM dba_sequences WHERE sequence_owner IN (:schemas) ORDER BY sequence_owner, sequence_name` | `cache_size`, `order_flag='N'`, `last_number` (high-water for Lakebase `setval`) | same |
| Identity column | `OWNER.TABLE.COLUMN` | `SELECT owner, table_name, column_name, generation_type, sequence_name, identity_options FROM dba_tab_identity_cols WHERE owner IN (:schemas) ORDER BY 1,2,3` | 12c identity hides a system sequence (`ISEQ$$_n`) | same |
| Scheduler job | `OWNER.JOB_NAME` | `SELECT owner, job_name, job_type, job_action, program_owner, program_name, schedule_type, start_date, repeat_interval, schedule_name, enabled, state, max_failures, max_run_duration, job_class, comments, last_start_date, next_run_date FROM dba_scheduler_jobs WHERE owner IN (:schemas) ORDER BY owner, job_name` | `state`, `failure_count`, `repeat_interval` complexity | same |
| Scheduler program / chain / window | `OWNER.PROGRAM_NAME` etc. | `SELECT owner, program_name, program_type, program_action, enabled FROM dba_scheduler_programs WHERE owner IN (:schemas)`; `dba_scheduler_chains`, `dba_scheduler_chain_steps`, `dba_scheduler_chain_rules`, `dba_scheduler_windows` (each `ORDER BY 1,2`) | chains = multi-task DAG (§6) | same |
| Job history | (evidence, not a unit) | `SELECT owner, job_name, status, actual_start_date, run_duration, error# FROM dba_scheduler_job_run_details WHERE owner IN (:schemas) AND log_date > SYSTIMESTAMP - 90 ORDER BY log_date` | 90-day run/fail pattern for the tolerance record | same |
| Legacy `DBMS_JOB` | `OWNER.JOB` | `SELECT schema_user, job, what, interval, broken, next_date FROM dba_jobs ORDER BY schema_user, job` | `broken='Y'`; still in production on 11g estates | same |
| Synonym | `OWNER.SYNONYM_NAME` | `SELECT owner, synonym_name, table_owner, table_name, db_link FROM dba_synonyms WHERE owner IN (:schemas) OR owner='PUBLIC' ORDER BY owner, synonym_name` | `db_link IS NOT NULL` = external ref; `owner='PUBLIC'` = shared name | same |
| Database link | `OWNER.DB_LINK` | `SELECT owner, db_link, username, host, created FROM dba_db_links ORDER BY owner, db_link` (never select from `SYS.LINK$`) | any row = external reference; the remote catalog is a separate estate | same |
| External / directory | `OWNER.TABLE_NAME` | `SELECT owner, table_name, type_name, default_directory_name, location FROM dba_external_tables` + `dba_external_locations`; `SELECT directory_name, directory_path FROM dba_directories` | file-based sources for the backfill plan | same |
| Dependency | edge `REFERENCED -> NAME` | `SELECT owner, name, type, referenced_owner, referenced_name, referenced_type, referenced_link_name FROM dba_dependencies WHERE owner IN (:schemas) ORDER BY owner, name` | compile-time edges = FACT source for §2 | same |
| Type / collection | `OWNER.TYPE_NAME` | `SELECT owner, type_name, typecode, attributes, methods FROM dba_types WHERE owner IN (:schemas)`; `dba_coll_types` | object types feeding `TABLE()` casts | same |
| Repo files | path | globs: `**/*.sql`, `**/*.pks`, `**/*.pkb`, `**/*.pls`, `**/*.plb`, `**/*.prc`, `**/*.fnc`, `**/*.trg`, `**/*.vw`, `**/*.seq`, `**/*.ddl`; SQL*Plus scripts = any of those containing `^\s*(SET|SPOOL|WHENEVER|DEFINE|COLUMN|EXEC|@@?|PROMPT|ACCEPT)\b`; shell wrappers `**/*.sh`,`**/*.ksh` calling `sqlplus`/`sqlldr`/`expdp`; `**/*.ctl` (SQL*Loader) | file lines; `/` terminators = statement count; `&var` count = parameter surface | repo read |

Repo census key for file-borne units is `OWNER.NAME` when the file has a `CREATE [OR REPLACE] <type> owner.name`
header, else `<schema-from-context>.<FILE_STEM>` (SQL*Plus scripts, loose `MERGE`/report SQL). Compare the repo
census with the dictionary census: a `PACKAGE BODY` in the dictionary with no file is a `hidden-consumer` flag for
the inventory; a file with no dictionary object is dead code or a different environment.

Albion: `api_legacy/plsql/pkg_policy_inquiry.sql` enumerates as `ODS.PKG_POLICY_INQUIRY` (spec + body, 2 members,
both `RETURN SYS_REFCURSOR`), reads `ods_policy_360`, `ods_claims`; no dictionary is reachable, so the repo census
is the census, and `docs/feed_inventory.md` supplies the GoldenGate edges into `ODS`.

## 2. Lineage extraction

Two evidence sources, always both: `dba_dependencies` (compile-time, FACT) and source text (statement-level
reads/writes, FACT when the referenced name resolves statically). An edge is **FACT** when it is in
`dba_dependencies` or the statement names a fixed `[owner.]object` that the census resolves (directly, through a
same-database synonym, or through a `%TYPE`/`%ROWTYPE` anchor). An edge is **INFERRED** when the object name is
built at runtime or lives outside the census, and the census row names the risk. Anything else is
**UNVERIFIABLE** and fails the round-trip: the analyzer has a completeness pass that walks every lineage-bearing
keyword (`FROM`/`JOIN`/`INSERT INTO`/`UPDATE`/`DELETE`/`MERGE INTO`/`TRUNCATE`, `EXECUTE IMMEDIATE`, `OPEN ... FOR`,
`DBMS_MVIEW.REFRESH`, qualified calls) and emits an `UNVERIFIABLE` edge with a named risk whenever no rule consumed
the operand (quoted identifiers, `UPDATE (subquery)`, table functions not in the census, `EXECUTE IMMEDIATE` on an
expression or an unassigned variable, `DBMS_SQL`/`UTL_*` calls, `X.Y(...)` where `X` is no known schema or package).
Unsupported syntax therefore surfaces as a failed run, never as a silently missing edge; extend the rule or record
the construct in `06_decisions.md`. A fixed name that the census does not
contain (Albion's `ods_policy_360`, whose DDL is not in the repo) is still a FACT edge; the *node* is recorded with
`status=not-in-census` and becomes an inventory gap for 2-estate_inventory, not a lineage uncertainty.

| Object class | Reads (FACT) | Writes (FACT) | INFERRED cases (named risk) |
|---|---|---|---|
| View / MV | every `FROM`/`JOIN` table, view, MV, synonym-resolved object; `@dblink` targets are edges to an external estate node | MV writes its container table; MV log rows are edges `MASTER -> MLOG$_MASTER` | `@dblink` where `dba_db_links` is not readable (`risk=external-db-link`); `TABLE(fn(...))` (`risk=pipelined-function`) |
| Package / procedure / function | `SELECT ... INTO`, `CURSOR c IS SELECT`, `OPEN c FOR SELECT` (static), `FOR r IN (SELECT ...)`, `%TYPE`/`%ROWTYPE` anchors, called subprograms (edge to `OWNER.PKG.MEMBER`) | `INSERT INTO`, `UPDATE`, `DELETE FROM`, `MERGE INTO`, `FORALL ... INSERT/UPDATE/DELETE`, `EXECUTE IMMEDIATE '<literal DDL/DML>'` with a constant string, `seq.NEXTVAL` (edge `PKG -> SEQ` typed `consumes-sequence`) | `EXECUTE IMMEDIATE` with concatenated identifiers (`risk=dynamic-sql`, record the literal prefix e.g. `INSERT INTO poladm.<var>`), `OPEN c FOR l_sql`, `DBMS_SQL.*`, `TABLE(CAST(... AS type))`, `%ROWTYPE` of a synonym to a dblink, `DBMS_*` calls that read/write outside SQL (`UTL_FILE`, `UTL_HTTP`, `DBMS_AQ`, `DBMS_PIPE`, `DBMS_LOB.LOADFROMFILE`: `risk=external-io`), `AUTHID CURRENT_USER` units (`risk=invoker-rights`, the referenced schema depends on the caller) |
| Trigger | the base table (`:OLD`), any `SELECT` in the body, called subprograms | the base table (`:NEW` is an in-flight write), every DML in the body, `seq.NEXTVAL`; the trigger's *transitive* side-effect closure (its own writes/`NEXTVAL`, plus those of every routine it calls, recursively, cycle-safe, plus the triggers on the tables that closure writes) is added to every unit whose write of the base table fires one of the trigger's declared events (`BEFORE INSERT OR UPDATE OF col` fires for `INSERT`, `UPDATE`, `MERGE`; not for `DELETE` or `TRUNCATE`; a `MERGE` with `DELETE WHERE` also fires `DELETE` triggers); every `writes` edge carries its events (`ops=INSERT|UPDATE`) and the fan-out edge records `detail="trigger fan-out via TRG -> callee"` | body dynamic SQL as above; `WHEN` clause referencing `SYS_CONTEXT` (`risk=session-context`) |
| Table / index | `CREATE TABLE ... AS SELECT` (also `GLOBAL TEMPORARY ... AS (SELECT ...)`, `AS WITH ...`): every source of the subquery is a `reads` edge of the new table; `CREATE [UNIQUE|BITMAP] INDEX ix ON t (...)` is a `defines-on` edge `IX -> T` (function-based columns, `TABLESPACE`/`LOCAL` clauses do not matter) | a plain `CREATE TABLE` owns its text (`REFERENCES ... ON DELETE CASCADE` is not DML) and draws no edge | an index whose target is not a plain `ON name (` (quoted identifier, `ON CLUSTER c`) -> `UNVERIFIABLE risk=unparsed-index-target` rather than a silent omission |
| Sequence | none | none; edges point *at* it | none. Record `last_number` for Lakebase `setval` parity |
| Scheduler job / program / chain | `job_action`/`program_action` parsed like an anonymous block: every named subprogram is a `schedules` edge; chain steps -> programs | none directly | `job_type='EXECUTABLE'` or `EXTERNAL_SCRIPT` (`risk=os-script`), `job_action` referencing `&`/bind-like placeholders, `event_condition` jobs (`risk=aq-event`) |
| SQL*Plus script | tables in embedded SQL; `@file`/`@@file`/`START` edges to other scripts (resolve relative to the script dir then `SQLPATH`) | embedded DML/DDL; `SPOOL` target (edge `SCRIPT -> FILE`) | `&var`/`&&var` inside identifiers (`risk=substitution-in-identifier`); `HOST`/`!` lines (`risk=os-shell`); `@file` not found in repo (`risk=missing-include`) |
| Synonym | resolves to its target *even when the synonym itself is in the census* (a private synonym shares the schema namespace with tables, so an enumerated `ODS.POLICY` synonym row never satisfies a lookup of `ods.policy`; the reader's edge goes to `POLADM.POLICY`); the synonym row stays and draws one `alias-of` edge to its target (FACT, INFERRED over a link, `not-in-census` target node when missing) | n/a | synonym with `db_link` (`risk=external-db-link`); synonym to a missing object (`risk=dangling-synonym`, the edge goes to the `not-in-census` target node) |

| GoldenGate / external feeds | `docs/feed_inventory.md`-style manifests, `.prm` files (`MAP src.t, TARGET ods.t`) -> edge `SOURCE_DB.T -> ODS.T` typed `replication` | n/a | replication lag expectations (`risk=freshness`, Albion: 26h-stale ODS behind a "real-time" SOAP API) |

Resolution order for an unqualified name inside PL/SQL: local variable/cursor -> package member -> same-schema
object -> private synonym -> PUBLIC synonym -> `AUTHID` rule. A *qualified* `OWNER.NAME` never falls through to a
same-named PUBLIC synonym (`claims.broker` is `CLAIMS.BROKER`, `not-in-census` if unknown, even when `PUBLIC.BROKER`
exists). Names declared by a statement's `WITH` clause (including recursive ones) are statement-local aliases, not
objects: their bodies are scanned for base-table reads, the alias itself is never a node, and the scope ends at the
statement. Record the resolution used on the edge. Quoted identifiers keep case; unquoted are upper-cased before lookup.
Comment stripping is lexical: `--` and `/* */` inside `'...'` (with `''`), `q'X...X'` (any single-character delimiter,
`[({<` closing with their partner) or `"quoted"` identifiers are text, so a literal such as `'-- not a comment'` never
hides the `FROM` that follows it. The same lexer bounds statements: a `CREATE [MATERIALIZED] VIEW` ends at the first
`;` outside a literal (`SELECT 'a;b' ... FROM t` keeps its `FROM`), a `DBMS_SCHEDULER`/`DBMS_RLS`/`DBMS_REDACT` call
ends at its balanced `)` (a `);` inside a `program_action` block does not), and named arguments are split on top-level
commas only (`start_date => TO_TIMESTAMP_TZ('...', '...')` is one value). `CREATE UNIQUE|BITMAP INDEX`,
`GLOBAL|PRIVATE TEMPORARY TABLE`, `[NON]EDITIONABLE`, `[NO] FORCE VIEW` and `PUBLIC` modifiers do not change the census
class. SQL*Plus directives may be indented. A file that mixes DDL with top-level `INSERT`/`MERGE`/`UPDATE`/`DELETE`/
`TRUNCATE` (outside every PL/SQL unit) gets one extra `DML SCRIPT` row named after the file that owns those writes;
`ON DELETE CASCADE` and `GRANT ... DELETE ON` are not DML. `DELETE FROM t` is a write only: the `FROM` after `DELETE`
is never a read, while `FROM`/`IN (SELECT ... FROM u)` subqueries inside the same `DELETE` remain reads of `u`.

## 3. Unit definition

**OLTP profile (Lakebase).** One unit = one *write set*: a table plus every constraint, index, trigger, and
sequence it depends on, plus every package/procedure whose FACT write edges touch that table, plus the trigger
fan-out writes. Application-facing contracts (`SYS_REFCURSOR` functions, `OUT` parameters, `RAISE_APPLICATION_ERROR`
codes the app parses) are part of the unit because Postgres function signatures must match the SOAP/JDBC caller.
Fixture: `POLICY` unit = `POLICY` + 7 constraints + 2 indexes + `TRG_POLICY_BIU` + `POLICY_SEQ` + `AUDIT_SEQ` +
`PRC_LOG_EVENT` + `POLICY_AUDIT_LOG` (trigger fan-out) + `PKG_POLICY_RENEWAL` (writes `POLICY`, `PREMIUM_TXN`) +
`MRG_POLICY_FROM_STG` + `STG_POLICY_FEED`. Cut the unit when two write sets share a table and both are needed:
mark it `shared` and migrate the table with the first, the second procedure alone.

**Analytical profile (Delta/DBSQL).** One unit = one *output*: a view/MV/report query plus the set-based
transformations that feed it, the MV logs it needs, the scheduler job/program/chain step that refreshes it, and
the SQL*Plus/report consumers that read it. Packages whose members only `OPEN ... FOR SELECT` (Albion
`PKG_POLICY_INQUIRY`) are read-only API units: they become SQL functions/views plus a serving-layer contract, and
the unit is the *pair* (converted query + consumer). Fixture: `MV_POLICY_PREMIUM_SUMMARY` unit = MV + 2 logs +
`JOB_NIGHTLY_RENEWAL` step 2; `V_BROKER_HIERARCHY` unit = view + `PUBLIC.BROKER` synonym + `FN_BROKER_PREDICATE`
(governance consumer).

`shared` = two units read or write the object with different profiles (e.g. `POLICY` is written by the OLTP unit
and read by `MV_POLICY_PREMIUM_SUMMARY`): the OLTP unit owns the table, the analytical unit consumes it through a
Lakebase synced table / lakehouse sync `[lakebase:references/synced-tables.md]`, `[lakebase:references/lakehouse-sync.md]`,
and the recon on the analytical side runs against the synced copy, not Lakebase directly. A scheduler job that
runs members of two units (fixture job = renewal + MV refresh) is split into one Lakeflow task per unit with a
`depends_on` edge `[jobs:SKILL.md#Multi-Task Workflows]`.

second, PySpark last. `Track` says where the construct lands: **A** = analytical Delta/DBSQL, **L** =
Lakebase/Postgres (OLTP profile), **J** = Lakeflow Jobs, **P** = Lakeflow Declarative Pipelines, **Py** = PySpark

appear. Runtime minimums are the ones in `[dbsql:sql-scripting.md#Runtime Version Reference]`.

`recon/canon.py`). The harness keys rules by name inside a profile, so one params set per rule: the params are the
*superset* that is safe for every Oracle type the rule applies to, and `applies_to` documents the type pairs.

| Row | Rule | `applies_to` | params | Why (Oracle behaviour it neutralises) |
|---|---|---|---|---|
| 1 | `empty_string_is_null` | `VARCHAR2,NVARCHAR2,CHAR,NCHAR,CLOB->STRING` | `policy: SET_AT_STOP_A`, `default: treat_empty_as_null` | Oracle stores `''` as NULL (§7 trap 1); a target that received `''` from a non-Oracle path (or from `concat_ws`, `rtrim`) must compare equal to the Oracle NULL. STOP A decides whether the *converted code* may ever produce `''`; the rule makes recon blind to the difference either way |
| 2 | `decimal_round` | `NUMBER,NUMBER(p,s),FLOAT,BINARY_FLOAT,BINARY_DOUBLE->DECIMAL(38,10),DECIMAL(p,s),DOUBLE` | `mode: half_even`, `places: 10` | `NUMBER` without scale keeps up to 38 significant digits at floating scale; the target `DECIMAL(38,10)` fixes scale at 10, and `AVG`/division add or drop scale (§7 traps 2, 25). Rounding both sides to 10 places half-even before comparing removes representation drift without hiding a real value change (which shows at the 2nd-6th decimal on money). For `NUMBER(p,s)` with `s<=10` the quantize is a no-op on the source and neutralises target scale growth. `BINARY_*` -> `DOUBLE` are IEEE on both sides; 10 places is still safe because differences beyond that are formatting |
| 3 | `datetime_utc_truncate_ms` | `DATE,TIMESTAMP,TIMESTAMP WITH TIME ZONE,TIMESTAMP WITH LOCAL TIME ZONE->TIMESTAMP_NTZ,TIMESTAMP` | `assume_source_tz_for_DATE: DBTIMEZONE` (documentation param; the adapter must attach the DB TZ to naive `DATE` values before the rule sees them) | `DATE` carries seconds (trap 3), `TIMESTAMP(9)` carries ns vs us on target, `TIMESTAMP WITH TIME ZONE`/`LTZ` render in session TZ (trap 4). Normalising both sides to UTC and truncating to ms compares the *instant* at a precision both engines share; a session-TZ misconfiguration then shows as a constant offset in Tier 3 rather than as noise |
| 4 | `rstrip_spaces` | `CHAR,NCHAR->STRING` | none | `CHAR(n)` blank-pads on Oracle, `STRING` does not (trap 5). Stripping trailing spaces on both sides compares the value the application meant. Ordered before row 1 in the harness field lists so a `CHAR` column of all blanks becomes `''` then NULL |
| 5 | `null_missing_equiv` | `*` | none | pivot cells, MV aggregate groups and `LEFT JOIN`-derived columns exist on one side only (traps 9, 15): a missing column/cell and a NULL cell mean the same thing |
| 6 | `collation_casefold` | `STRING` | `enabled_if: NLS_COMP=LINGUISTIC or UPPER()/NLS_UPPER() compares found in census` | off by default because Oracle's default `NLS_COMP=BINARY` is case-sensitive like `UTF8_BINARY`. Enabled only when the census finds linguistic comparison settings or `UPPER(a)=UPPER(b)` idioms (Albion `pkg_policy_inquiry` upper-cases identifiers before comparing), and then the target column also gets `COLLATE UTF8_LCASE` (§5 rule 33) so recon and production agree |
| 7 | `uuid_normalize` | `RAW(16)->STRING` | `enabled_if: SYS_GUID() default or RAWTOHEX consumers found in census` | `SYS_GUID()` is 16 raw bytes, rendered `RAWTOHEX` upper-case without hyphens; target `uuid()`/`UUID` renders lower-case hyphenated (§5 rules 88, 90). Comparing the normalised 32-hex form is the only fair compare |
| 8 | `identity` | `*` | none | explicit no-op for `BIGINT`, `INTERVAL`, `BOOLEAN`, `BINARY` hash compares, and for surrogate keys that are *excluded* from Tier 3 rather than canonicalized |

Harness gaps (filed in the PR body, never faked here): (a) per-type params for the same rule inside one profile
(`decimal_round` at 2 places for `NUMBER(12,2)` and 10 for bare `NUMBER`) — the profile is keyed by rule name; (b)
a `datetime_assume_tz` rule that attaches a source TZ to naive `DATE` values before UTC normalisation (today it must
happen in the adapter query via `FROM_TZ(CAST(col AS TIMESTAMP), DBTIMEZONE)`); (c) a `hex_case_normalize` for
`RAW(n)` with `n<>16`; (d) `char_semantics_truncate(n)` to compare `VARCHAR2(n BYTE)`-truncated source strings with
untruncated target strings. Not needed: `datetime_grid_333` (Sybase/SQL Server datetime grid) — Oracle has no
3.33 ms grid.

## 9. Governance discovery

Read-only dictionary queries; each feeds `governance-mapping` and D8 as inventory objects. Minimum privilege is
`SELECT_CATALOG_ROLE` (or `SELECT ANY DICTIONARY`) for `DBA_*`; `ALL_*`/`USER_*` variants need only `CREATE SESSION`
but see less, and the report must say which was used. Nothing here is recreated on Oracle; the factory never grants,
revokes, or alters a policy on the source.

| Surface | Query | Feeds | UC landing (`[uc:...]`) / `GAP` |
|---|---|---|---|
| Object grants | `SELECT grantee, owner, table_name, grantor, privilege, grantable, hierarchy FROM dba_tab_privs WHERE owner IN (:schemas) ORDER BY owner, table_name, grantee` | grants inventory (D8) | `GRANT SELECT/MODIFY/EXECUTE ON TABLE/FUNCTION` `[uc:references/1-access-control.md#GRANT / REVOKE (SQL)]`; `INSERT`/`UPDATE`/`DELETE` collapse to `MODIFY` (finer split = `GAP`, noted per grantee); `grantable='YES'` (`WITH GRANT OPTION`) has no UC form -> ownership or `MANAGE` |
| Column-level grants | `SELECT grantee, owner, table_name, column_name, privilege FROM dba_col_privs WHERE owner IN (:schemas) ORDER BY 2,3,4,1` | column-security inventory | no column-level `SELECT` grant in UC: column mask `[uc:references/4-fine-grained-access.md#Column Masks]` or a projecting view + grant; fixture `GRANT SELECT (policy_no, ...) ON poladm.policy TO poladm_app` -> view `policy_app_v` |
| Roles | `SELECT role, authentication_type, common, oracle_maintained FROM dba_roles WHERE oracle_maintained='N' ORDER BY role` | principal map | UC group per role (`[uc:references/1-access-control.md#Securable Hierarchy]` groups); password-protected roles (`authentication_type='PASSWORD'`) -> `GAP` |
| Role membership | `SELECT grantee, granted_role, admin_option, default_role FROM dba_role_privs WHERE granted_role IN (SELECT role FROM dba_roles WHERE oracle_maintained='N') ORDER BY granted_role, grantee` | group membership; nested roles = nested groups | `admin_option='YES'` -> group manager; `default_role='NO'` (`SET ROLE` at runtime) -> `GAP` (no session-activated groups) |
| System privileges | `SELECT grantee, privilege, admin_option FROM dba_sys_privs WHERE grantee IN (:principals) ORDER BY grantee, privilege` | over-privilege report | `SELECT ANY TABLE`/`CREATE ANY *` -> catalog-level `USE`/`CREATE` grants; `EXEMPT ACCESS POLICY` (VPD bypass) -> must be a row-filter exemption group; `UNLIMITED TABLESPACE`, `ALTER SYSTEM` -> drop |
| Ownership-implied rights | `SELECT owner, COUNT(*) objects FROM dba_objects WHERE owner IN (:schemas) GROUP BY owner`; users: `SELECT username, account_status, authentication_type, profile, created FROM dba_users WHERE oracle_maintained='N'` | owner map | schema owner = UC schema `OWNER` `[uc:references/1-access-control.md#Ownership]`; application schemas with `account_status='LOCKED'` become service principals |
| `PUBLIC` grants | `SELECT owner, table_name, privilege FROM dba_tab_privs WHERE grantee='PUBLIC' AND owner IN (:schemas)`; `SELECT synonym_name, table_owner, table_name FROM dba_synonyms WHERE owner='PUBLIC' AND table_owner IN (:schemas)` | exposure report | `PUBLIC` -> `account users` group only after an explicit STOP; default is `GAP`-flagged and re-granted to named groups. Fixture: `GRANT SELECT ON ods.v_broker_hierarchy TO PUBLIC` |
| VPD / FGAC (row security) | `SELECT object_owner, object_name, policy_group, policy_name, pf_owner, package, function, sel, ins, upd, del, enable, policy_type, static_policy FROM dba_policies WHERE object_owner IN (:schemas)`; predicate source from `dba_source` of the policy function; `dba_sec_relevant_cols` for column-relevant policies | row-security inventory | row filter function + `ALTER TABLE ... SET ROW FILTER` `[uc:references/4-fine-grained-access.md#Row Filters]`; predicate text is *rewritten* by hand: `SYS_CONTEXT('USERENV','SESSION_USER')` -> `session_user()`/`is_account_group_member()` `[uc:references/4-fine-grained-access.md#Identity Functions]`; predicates using application contexts (`SYS_CONTEXT('ALBION_CTX', ...)`) or `ins/upd/del` policies -> `GAP` (UC filters apply to reads; writes need the procedure to enforce). Lakebase: `CREATE POLICY ... USING (...)` `[pg17:sql-createpolicy.html]`, `[pg17:ddl-rowsecurity.html]` |
| Data Redaction | `SELECT object_owner, object_name, policy_name, expression, enable FROM redaction_policies WHERE object_owner IN (:schemas)`; `SELECT object_owner, object_name, column_name, function_type, function_parameters, regexp_pattern FROM redaction_columns` | column-mask inventory | column mask `[uc:references/4-fine-grained-access.md#Column Masks]`: `FULL` -> constant, `PARTIAL`/`REGEXP` -> mask function reproducing the pattern, `RANDOM` -> `GAP` (non-deterministic), `NULLIFY` -> `NULL`. The `expression` (who sees clear text) -> `is_account_group_member()` in the mask; fixture `PARTY_DOB_REDACT` `m1d1y` keeps year -> `make_date(year(dob),1,1)` |
| Transparent Sensitive Data Protection (23ai), Label Security | `dba_tsdp_policy_*`, `dba_sa_*` (only if `OLS` installed) | column-mask inventory | `GAP` unless the policy reduces to a mask |
| Audit | Unified: `SELECT policy_name, audit_option, object_schema, object_name, enabled_option FROM audit_unified_policies WHERE object_schema IN (:schemas) OR object_schema='NONE'`; enabled: `SELECT * FROM audit_unified_enabled_policies`; traditional: `SELECT * FROM dba_obj_audit_opts WHERE owner IN (:schemas)`; `SELECT * FROM dba_stmt_audit_opts`; FGA: `SELECT object_schema, object_name, policy_name, policy_column, audit_condition, statement_types FROM dba_audit_policies` | audit expectations (D8) | UC audit via system tables `[uc:references/5-system-tables.md]` (`system.access.audit`); FGA `audit_condition` (audit only when predicate true) -> `GAP` (log everything, filter downstream) |
| Governance-relevant synonyms and links | `SELECT owner, synonym_name, table_owner, table_name, db_link FROM dba_synonyms WHERE db_link IS NOT NULL`; `SELECT owner, db_link, username FROM dba_db_links` | external-access inventory | link credentials are never read (`SYS.LINK$` is off limits); the remote object is an external system in D8 |
| Proxy users, `AUTHID`, definer's-rights procedures | `SELECT proxy, client, authentication FROM proxy_users`; `SELECT owner, object_name, authid FROM dba_procedures WHERE authid='DEFINER' AND owner IN (:schemas)` (also `dba_objects` join for packages) | privilege-escalation report | definer-rights units grant table access *through* the code: on DBSQL the caller needs direct grants (`SQL SECURITY INVOKER` only, §6); list each such unit as a D8 row |
| Encryption at rest, network | `SELECT owner, table_name, column_name, encryption_alg FROM dba_encrypted_columns`; `v$encrypted_tablespaces` (needs `SELECT ANY DICTIONARY`) | compliance notes | platform encryption on target; column-level TDE has no per-column knob -> note only |

Every `GAP` row carries the source policy verbatim as an inventory object with `status=GAP` so D8 can decide
(compensating view, application enforcement, or accepted loss). Recon runs under an unfiltered principal on both
engines; a policy is never emulated in the recon query.

## 11. Risk heuristics

Per-object inputs the census computes from §1 signals and §2 edges; thresholds are starting points for the
inventory's complexity rank, the tolerance record can move them.

| Input | Source | Low | Medium | High |
|---|---|---|---|---|
| Source lines (`dba_source` count, or file lines) | §1 | `< 150` | `150-800` | `> 800` or wrapped |
| Procedural depth (max nesting of `BEGIN`/`LOOP`/`IF`) | text | `<= 2` | `3-4` | `>= 5` |
| Cursor loops with DML inside (row-by-row writes) | text: `LOOP` containing `INSERT/UPDATE/DELETE/MERGE` | 0 | 1 | `>= 2` or nested |
| `BULK COLLECT`/`FORALL` blocks | text | 0 | `1-2` (set-based rewrite is mechanical) | `SAVE EXCEPTIONS` present |
| Dynamic SQL (`EXECUTE IMMEDIATE`, `DBMS_SQL`, `OPEN ... FOR <var>`) | §2 INFERRED edges | 0 | literal statements only | concatenated identifiers or user input |
| Exception handlers | text | named exceptions with `RAISE` | `WHEN OTHERS` with logging + re-raise | `WHEN OTHERS THEN NULL`/status-code swallow (behaviour change needed) |
| Transaction control (`COMMIT`/`ROLLBACK`/`SAVEPOINT` count, `AUTONOMOUS_TRANSACTION`) | text | 0-1 `COMMIT` at end | `SAVEPOINT` or mid-loop `COMMIT` | `AUTONOMOUS_TRANSACTION`, `SET TRANSACTION`, `LOCK TABLE`, `FOR UPDATE SKIP LOCKED` |
| Vendor-function density (`DBMS_*`, `UTL_*`, `SYS_CONTEXT`, `CONNECT BY`, `PIVOT XML`, `MODEL`, `KEEP`, `XML*`, `JSON_TABLE`, `REGEXP_*` with 4+ args) per 100 lines | text | `< 1` | `1-5` | `> 5` or any `UTL_FILE/UTL_HTTP/DBMS_AQ/DBMS_PIPE/DBMS_LOB.LOADFROMFILE` |
| External calls (`@dblink`, Java/EXTPROC, `HOST`, `sqlldr`) | §2 | 0 | synonym over link, read-only | write over link, OS calls |
| Trigger fan-out (triggers on written tables x their writes) | §2 | 0 | 1 trigger, same-table derivations | trigger writing other tables, calling packages, or autonomous logger |
| Sequence coupling (`NEXTVAL` in DML / `CURRVAL` reads) | text | identity-able (one table) | shared sequence across tables | `CURRVAL` consumed, gapless expectations in code |
| Type traps present (`NUMBER` no scale, `DATE` compared/`BETWEEN`, `CHAR` keys, `TIMESTAMP WITH TIME ZONE`, `RAW`) | §1 columns x §2 reads | none | 1-2 kinds | `CHAR` or `NUMBER`-no-scale used as a join key |
| Hidden consumers (`SYS_REFCURSOR` out, `OUT` params, `DBMS_OUTPUT`, `SPOOL`, `UTL_SMTP`) | text | none | one typed `OUT` | ref cursor consumed by an external API (Albion SOAP) |
| Scheduler complexity | §1 | single job, daily cron | chain with `run_if`-mappable rules | event/AQ jobs, `EXECUTABLE` programs, DST-sensitive `BYHOUR` near a change, non-cron `repeat_interval` |
| Governance attachments (VPD, redaction, column grants, `PUBLIC`, definer-rights) | §9 | plain grants to roles | one policy, expressible as filter/mask | app-context predicates, `RANDOM` redaction, `PUBLIC` writes, definer-rights units used for privilege elevation |
| MV refresh mode | §1 | `COMPLETE ON DEMAND` | `FAST ON DEMAND` with logs | `FAST ON COMMIT`, `ENABLE QUERY REWRITE` relied upon by consumers |
| Object status | §1 | `VALID` | `INVALID` but recompilable | `INVALID` referencing missing objects (dead code candidate) |

Suggested rank: `High` on any High cell -> `complex` (hand-migrated, two reviewers); otherwise `>= 3` Medium ->
`medium`; else `simple` (Lakebridge + §5 review). Fixture ranks: `PKG_POLICY_RENEWAL` complex (dynamic SQL,
`SAVEPOINT`, `FOR UPDATE SKIP LOCKED`, swallow, autonomous logger call); `TRG_POLICY_BIU` complex (fan-out to
logger); `MRG_POLICY_FROM_STG`, `V_BROKER_HIERARCHY`, `MV_POLICY_PREMIUM_SUMMARY`, `JOB_NIGHTLY_RENEWAL`,
`RPT_POLICY_PAGE` medium; `V_PREMIUM_BY_TXN_TYPE`, tables, sequences simple. Albion `PKG_POLICY_INQUIRY` medium
(ref-cursor API consumer, `UPPER`/`REPLACE` identifier normalisation implies `collation_casefold` decision, no DML).
