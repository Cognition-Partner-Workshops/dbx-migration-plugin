## Type map

`Delta` is the analytical track, `Lakebase PG` the OLTP front door. `canon` = harness rule in `canonicalization.json`; `GAP` = not in the harness (PR body).

| Source | Delta | Lakebase PG | Loss / canon |
|---|---|---|---|
| `BIT` | `BOOLEAN` | `BOOLEAN` | 0/1/'TRUE' accepted in source; Tier 2 null-rate |
| `TINYINT` (0..255) | `SMALLINT` (Delta `TINYINT` is signed) | `SMALLINT` | none |
| `SMALLINT` / `INT` / `BIGINT` | same | `SMALLINT` / `INTEGER` / `BIGINT` | none |
| `INT IDENTITY` | `BIGINT GENERATED BY DEFAULT AS IDENTITY`: `INSERT` the source keys, then `ALTER TABLE t ALTER COLUMN id SYNC IDENTITY` before the first generated insert (`GENERATED ALWAYS` rejects explicit values; identity columns disable concurrent writes, so tables written by concurrent `BEGIN ATOMIC` callers get plain `BIGINT` + a generated surrogate elsewhere) | `BIGINT GENERATED BY DEFAULT AS IDENTITY`; `setval(pg_get_serial_sequence(...), max(id))` after load | source keys preserved, so FK/Tier 3 recon keys on them; `identity` |
| `DECIMAL(p,s)` / `NUMERIC` | `DECIMAL(p,s)` | `NUMERIC(p,s)` | exact: `identity` at any scale; a recomputed column is `cast(... AS DECIMAL(p,s))` in the converted SQL, never `decimal_round` (places=4 would equate values differing in digit 5+) |
| `MONEY` / `SMALLMONEY` | `DECIMAL(19,4)` / `DECIMAL(10,4)` | `NUMERIC(19,4)` / `(10,4)` | loaded: `identity`; source rounds every operation to 4 places, so only columns the target recomputes from `MONEY` get `decimal_round` places=4 `half_up` |
| `FLOAT` / `REAL` | `DOUBLE` / `FLOAT` | `DOUBLE PRECISION` / `REAL` | relative tolerance in the tolerance record |
| `CHAR(n)` | `STRING` (or `STRING COLLATE UTF8_BINARY_RTRIM`) | `CHAR(n)` | blank padding; `rstrip_spaces` |
| `VARCHAR(n)` / `NVARCHAR(n)` / `NCHAR(n)` | `STRING` | `VARCHAR(n)` / `TEXT` | CI collation; `collation_casefold` when census says `_CI_`, plus `rstrip_spaces` |
| `VARCHAR(MAX)` / **ASE** `TEXT` / `UNITEXT` | `STRING` | `TEXT` | ASE `TEXT` not comparable in source: Tier 2 `length()`/hash only |
| `BINARY` / `VARBINARY` / **ASE** `IMAGE` | `BINARY` | `BYTEA` | Tier 2 `octet_length`, `sha2` |
| `ROWVERSION` / `TIMESTAMP` | drop or load-time `BINARY` | `BYTEA` | engine-assigned; exclude from recon |
| `DATE` / `SMALLDATETIME` | `DATE` / `TIMESTAMP_NTZ` | `DATE` / `TIMESTAMP` | none |
| `DATETIME` (**ASE** too) | `TIMESTAMP_NTZ` | `TIMESTAMP` | 1/300 s grid (`.000/.003/.007`) is exact in µs: loaded columns `identity`; only columns the target recomputes at ms/µs (`DATEADD`, arithmetic) use `datetime_grid_333` (10 ms grid, equates `.000/.003` -> tolerance record; exact fit is `GAP: datetime_tolerance_ms`) |
| `DATETIME2(p)` / `TIME(p)` / **ASE** `BIGDATETIME` | `TIMESTAMP_NTZ` / `TIME` | `TIMESTAMP` / `TIME` | p <= 6 exact: `identity`; p = 7 loses the 100 ns digit: extract the source at µs the way the loader did (`LEFT(CONVERT(VARCHAR(27),x,121),26)`), `GAP: datetime_truncate_us`; never `datetime_utc_truncate_ms` (hides µs) |
| `DATETIMEOFFSET(p)` | `TIMESTAMP` (UTC-normalised) | `TIMESTAMP WITH TIME ZONE` | offset lost: keep `offset_minutes` if read; p <= 3 `datetime_utc_truncate_ms` (UTC-normalises, lossless at ms); p > 3 normalise in the extraction (`SWITCHOFFSET(x,'+00:00')`) then as `DATETIME2(p)` |
| `UNIQUEIDENTIFIER` | `STRING` (36-char) | `UUID` | upper vs lower case; `uuid_normalize` |
| `XML` / `SQL_VARIANT` | `STRING` (+ type tag) | `XML` / `TEXT` | `GAP: xml_canonicalize`, `GAP: variant_split` |
| `HIERARCHYID` / `GEOGRAPHY` / `GEOMETRY` | `STRING` / `GEOGRAPHY(srid)` / `GEOMETRY(srid)` | `TEXT` / PostGIS | hand-convert |
| TVP / `CURSOR` variable / **ASE** `UNSIGNED INT` | temp table or `ARRAY<STRUCT>` / rewrite / `BIGINT` | n/a / n/a / `BIGINT` | signature change |
